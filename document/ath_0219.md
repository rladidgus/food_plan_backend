## 1. 식단 생성 칼로리 불일치 수정

### 🔴 문제 상황
- 사용자의 목표 칼로리(예: 2483 kcal)에 비해 생성된 식단의 총 열량(1900 kcal, 2000 kcal 등)이 현저히 낮게 나오는 현상 발생.
- GPT 모델이 `±5%` 범위 조건을 엄격하게 따르지 않음.

### ✅ 해결 방법 (`app/meal_plan_ai.py`)
- **수학적 계산을 Python 코드로 이관**: GPT에게 "계산해"라고 시키지 않고, 코드 레벨에서 정확한 Min/Max 칼로리를 미리 계산하여 프롬프트에 주입.
- **프롬프트 강화**:
    - **Minimum/Maximum Calorie Range 명시**: `(Target * 0.95)` ~ `(Target * 1.05)` 범위를 구체적인 숫자로 제시했습니다.
    - **끼니별 권장 칼로리 가이드 추가**: 아침:점심:저녁 비율(3:4:3)에 맞춘 권장 칼로리를 계산하여 힌트로 제공했습니다.
    - **강력한 제약 조건 추가**: "Do NOT output a lower value" 등의 문구를 추가하여 과소 섭취(Under-eating)를 방지했습니다.

```python
# app/meal_plan_ai.py 변경 예시
target = prompt.get("target_calorie", 0) or 2000
min_cal = int(target * 0.95)
max_cal = int(target * 1.05)

user_content = (
    ...
    f"1. Target Calorie: {target} kcal\n"
    f"2. Strict Total Calorie Range: {min_cal} ~ {max_cal} kcal\n"
    ...
)
```

## 2. API 500 에러 및 CORS 오류 수정

### 🔴 문제 상황
- `/api/user/goal` 엔드포인트 호출 시 **500 Internal Server Error** 발생.
- 500 에러로 인해 CORS 헤더가 누락되어 프론트엔드에서는 **CORS Error**로 표시됨.

### 🔍 원인 분석
- **Pydantic 객체 직렬화 오류**: `UserGoalWithPlanResponse` 모델에서 `plan` 필드는 `dict` 타입을 기대하지만, 실제 코드에서는 `OneDayMealPlan` (Pydantic 객체)을 그대로 반환하여 Validation Error 발생.
- 서버 로그: `Input should be a valid dictionary, input: OneDayMealPlan(...)`

### ✅ 해결 방법 (`app/main.py`)
- 반환 시 `.model_dump()`를 사용하여 Pydantic 객체를 Dictionary로 변환하도록 수정.

```python
# app/main.py 수정 전
"plan": plan, 

# app/main.py 수정 후
"plan": plan.model_dump() if plan else None,
```
